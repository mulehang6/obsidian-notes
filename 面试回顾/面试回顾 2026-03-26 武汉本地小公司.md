### 5. 说一下Java中常用的集合？

分为两大类，Collection和Map
#### 1. Collection - List

- ArrayList，底层是动态数组，查询快，增删慢，因为增删可能涉及元素移动，最常用。
  
- LinkedList，底层是双向链表，增删快，查询慢，因为需要从头到尾遍历，也可以作为队列或者双端队列使用。

- Vector和ArrayList类似，不过加上了`synchronized`，线程安全，不过性能较差，平时很少用到。

#### 2. Collection - Set

- HashSet，底层基于HashMap实现，通过哈希值去重，查询效率比较高，但是不保证元素的顺序。

- LinkedHashSet在HashSet的基础上维护了插入顺序，所以他可以保证元素按照插入顺序遍历

- TreeSet底层是红黑树，可以对元素进行排序，默认自然排序，也可以传入自定义的比较器

#### 3. Collection - Queue

- LinkedList，可用作普通队列。

- PriorityQueue，优先级队列，底层通常是堆结构，出队顺序不是插入顺序，而是按照优先级排序。

- ArrayDeque，双端队列，底层是数组，既可以从队头操作，也可以从队尾操作，性能通常比LinkedList更好。

#### 4. Map

- HashMap，最常见，底层是数组 + 链表 + 红黑树，初始时是数组 + 链表，超过一定长度之后就转变为红黑树。线程不安全，允许一个`null key`和多个`null value`。

- LinkedHashMap，在HashMap的基础上维护了双向链表，可以保证插入顺序，也可以实现==LRU缓存==

- TreeMap，底层是红黑树，可以按照key排序，适合需要有序遍历的场景。

- HashTable，早期线程安全的Map，方法加了`synchronized`，性能较差，不允许`null key`和`null value`，现在很少用。

- ConcurrentHashMap，线程安全的Map，适合高并发场景，相比HashTable，他的锁粒度更细，性能更好

### 6. 为什么ArrayList支持随机访问？

主要是因为他底层是基于数组的。

`ArrayList`底层维护的是一个`Obejct`数组，数组在内存中是连续的，所以可以直接通过下标访问对应的元素。

### 7. 你了解现在企业开发的架构吗？

目前主流的有三种：前后端分离、分布式、微服务。

#### 前后端分离

前端负责展示用户界面，后端负责处理Restful API 接口，数据库请求，鉴权等操作。

#### 分布式

如果系统访问量变大，或者业务模块变多，就会把应用服务、数据库，缓存、消息队列等组件分开部署

#### 微服务

如果系统访问量继续增大，那么就按照业务逻辑将原先的单个应用拆分成多个独立的相对小型的服务，比如用户服务，订单管理等，原先都是在同一个模块下，在微服务架构中，则解耦成了不同的模块，每个服务都可以独立开发，部署和扩容。服务与服务之间一般通过HTTP、RPC或者消息队列通信。Java企业中常用的技术栈是Spring Boot + Spring Cloud，比如注册中心(`Nacos`)、配置中心(`Nacos`)、网关(`Spring Cloud Gateway`)、服务调用(`Dubbo, gRPC`)、熔断限流(`Sentinel`)、链路追踪(`SkyWalking, OpenTelemetry`)等。

需要注意的是，微服务并不一定比单体更好，因为维护起来更加复杂，所以一般是业务规模上来以后再考虑微服务，而不是一上来拆分。
