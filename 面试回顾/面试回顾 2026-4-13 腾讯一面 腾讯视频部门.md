## 3. MySQL和Redis这些你们肯定用过，那你知道他们走的是什么协议吗？

他们都走的是TCP。

对于MySQL，他走的是MySQL独有的 MySQL Client/Server Protocol。这个协议会处理握手认证、SQL请求，结果集返回、错误码等信息。也可以走Unix socket，但远程连接主要就是TCP

对于Redis，走的是Redis独有的Redis Serialization Protocol，Redis客户端发送命令，比如set key value，get key，底层都会被编码成RESP格式，特点是简单高效，容易解析

## 4. MySQL的索引分哪几种？分别说一下他们的区别

### 1. 按数据结构分
- B+树索引。InnoDB默认就是这个，他适合等值查询、范围查询、排序、分组
  
- Hash索引。顾名思义，基于哈希表实现的索引，查询单个等值条件很快，但是不支持范围查询，也不支持排序，因为哈希之后的数组是无序的。InnoDB本身不支持用户显式创建Hash索引，但是也有自适应哈希索引
  
- 全文索引。主要用于文本内容搜索，比如文章，标题，评论中的关键词，适合`match against`这种场景，不是普通的精确匹配索引
  

### 2. 按功能分
- 主键索引。特殊的唯一索引，要求字段值唯一且不能为`null`。一张表只能有一个主键索引。InnoDB中，主键索引还是聚簇索引，数据行本身就存放在主键索引的叶子节点上
  
- 唯一索引。要求不能重复，但是可以为`null`，具体是否允许多个`null`与数据库的实际设计有关
  
- 普通索引。没有唯一性约束，也可以为`null`，主要的目的是为了加快查询
  
- 联合索引。是多个字段一起建立的索引，遵循最左前缀原则，也就是查询条件要先从左侧开始匹配，才能更好地利用索引
  
- 全文索引。

## 6. MySQL有个命令可以调出来日志，那是哪一条

如果只是普通的日志，那就是
```SQL
show variables like '%log%'
```

如果是查询慢日志
```SQL
show variables like 'slow_query_log'
```

如果是查看binlog
```SQL
show binary logs
```

如果想查看具体的事件
```SQL
show binary events in 'mysql-bin.000001'
```
## 7. 进程，线程和协程的区别，为什么进程的切换开销最大，线程其次，协程最小

进程：操作系统进行资源调度的基本单位，简单来说就可以看成是一个正在运行的应用实例，比如我用IDEA开了两个文件夹，那么此时就有两个IDEA的进程。
开销原因：
- 要切换地址空间：不同的进程有不同的虚拟内存空间，切换时通常要要切换页表。这也就意味着CPU的内存映射变了。
- TLB可能失效，页表切换后，TLB里的缓存可能很多都不能用了
- 要保存和回复完整的内核上下文：包括寄存器、程序计数器、内核栈、调度信息
- 可能伴随更多系统资源分配

线程：线程是进程中的独立执行单元，他们共享进程中的资源和内存；每个线程都有自己独立的栈和寄存器
开销原因：
- 仍然需要内核参与，线程是内核调度单位，切换要经过内核态
- 仍然要保存和回复线程上下文，比如寄存器、程序计数器、栈指针等
- 线程如果多了会有调度竞争，大量线程会带来调度开销、锁竞争、上下文切换频繁等问题

协程：比线程更加轻量，可在单线程中实现并发执行，需要显式调度。由程序运行时或者框架在用户态调度。
开销原因：
- 不需要内核参与调度，完全在用户态
- 不需要切换地址空间
- 只需要保存很少的上下文，通常只保存自己的栈、程序位置、局部状态等，比线程上下文轻
- 调度更可控，协程一般是协作式调度，比如到某个挂起点、IO等待点再切走，不像线程那样随时可能被操作系统抢占
