# Jewel UI 实现模式

## 主题与组件边界

1. 先定位现有主题入口、主题适配器和窗口宿主；沿用项目已验证的初始化方式，不要在叶子 Composable 重复创建主题。
2. 从目标版本已解析源码确认应使用的 Jewel 主题、组件、token、导入和模块。优先使用公开稳定 API，不要按旧代码推断 `IntUiTheme`、bridge 或图标 API。
3. 使用 Jewel 的设计 token 和现有组件形成 IntelliJ 风格界面；不要用大量硬编码颜色、间距或 Material 组件模拟同一外观。

## Compose 实现要求

- 上提业务状态，让渲染 Composable 保持可预览、可测试，并通过回调表达用户意图。
- 将副作用、数据访问和窗口控制放在状态层或协作层，而不是散落在组件渲染中。
- 对弹窗、列表、可编辑输入和滚动容器检查焦点、键盘导航、禁用态、可达性、缩放和主题切换。
- 对 Windows、macOS 和 Linux 的平台差异使用目标版本的官方行为作为依据，不要将某平台观测到的尺寸或滚动行为写死为通用规则。

## 实验 API 与互操作

- 只在需求明确时使用 `Experimental`、`Internal` 或 `ApiStatus` 注解的 API。将调用封装在窄适配层，注明已核验的 Jewel 版本、用途和替换风险。
- 涉及 Swing/Compose 互操作时，遵循目标版本 bridge/API 的初始化顺序。不要为修复层级或闪烁问题而随意启用实验性渲染管线；先确认平台限制和性能代价。
- 修改后检查浅/深色、DPI 缩放、窗口拖动、Popup / Tooltip / Menu 焦点、滚动、图标和 Markdown（如有）行为。
