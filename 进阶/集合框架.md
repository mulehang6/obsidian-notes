# 1. HashMap

## 1. hash方法的原理

源码：
```java
// jdk 8
static final int hash(Object key) {
    int h;
    return (key == null) ? 0 : (h = key.hashCode()) ^ (h >>> 16);
}
```

哪里用到了呢？看一下put方法的源码

```java
// jdk 8
public V put(K key, V value) {
    return putVal(hash(key), key, value, false, true);
}
```

### hash方法的作用

HashMap底层是通过数组的形式来实现的，初始大小是16，也就是说，最开始的时候，需要通过键的哈希码在16个大小的数组中选一个确定一个位置(索引)，怎么确定呢？

先记住这个结论：==通过(n - 1) && hash==，其中n为数组的长度，变量hash就是通过hash方法计算之后的结果。

理论上，哈希码(哈希值)是一个int类型，范围在-2147483648 到 2147483648之间，大约40亿，内存肯定是放不下的。HashMap扩容之前的数组长度又只有16，所以这样算的哈希值肯定是不能直接拿来用的，用之前要和数组的长度做与运算`(n - 1) && hash`，有些地方叫取模运算，有些也叫取余运算，得到下标才可以。

### 取模运算、取余运算、与运算

取模和取余严格来讲，是两种不同的运算。
在Java中，取余一般用%，取余则是`Math.floorMod`。区别如下：
- 如果操作数都是正数，那么结果是一样的。
- 如果是负数，那么取模的商会向负无穷靠近；取余则是0

例子：
```java
int a = -7;
int b = 3;

// a 对 b 取余
int remainder = a % b;
// a 对 b 取模
int modulus = Math.floorMod(a, b);

System.out.println("数字: a = " + a + ", b = " + b);
System.out.println("取余 (%): " + remainder);
System.out.println("取模 (Math.floorMod): " + modulus);

// 改变 a 和 b 的正负情况
a = 7;
b = -3;

remainder = a % b;
modulus = Math.floorMod(a, b);

System.out.println("\n数字: a = " + a + ", b = " + b);
System.out.println("取余 (%): " + remainder);
System.out.println("取模 (Math.floorMod): " + modulus);
```

输出：
```txt
数字: a = -7, b = 3
取余 (%): -1
取模 (Math.floorMod): 2

数字: a = 7, b = -3
取余 (%): 1
取模 (Math.floorMod): -2
```

何意味？

#### 1. 取余

余数的定义是基于常规除法的，所以他的符号总是与被除数相同，商趋向于0。

例如，对于 `-7 % 3`，余数是`-1`。因为`-7 % 3`可以有两种结果，一种是商`-2`，余`-1`，还有一种是商`-3`，余`2`。因为取余的商趋向于0，那么很显然这里的结果就应该是`-2`了

#### 2. 取模

取模也是基于除法的，只不过他的符号总是与除数相同，商趋向于负无穷。

例如，对于`Math.floolMod(7, -3)`，也有两种结果，同上，这里很显然就选商`-3`的情况。

#### 3. 与运算

当数组的长度是2^n时，有`hash & (length - 1) = hash % length`。为什么呢？

当数组长度是2^n时，`hash % length`相当于`hash >> n`，也就是把n右移了n位，此时就得到了`hash / 2^n`的商。被移动的部分，则是`hash % 2^n`，也就是余数。

`hash % length`的操作是求hash除2^n的余数。在二进制中，这个操作的结果就是hash的二进制中最低n位的值，例如26的二进制是11010，要算26 % 8，那么结果自然就是商3余2，正好与最低3位010相同。

当执行`hash & (length - 1)`时，本质上就是保留hash二进制表示的最低n位，其他高位都清零。
例如hash = 14，length = 2^3 
```txt
 1110
 0111
&---------
 0110
```

结果为6

```java
final Node<K,V> getNode(int hash, Object key) {
    // 获取当前的数组和长度，以及当前节点链表的第一个节点（根据索引直接从数组中找）
    Node<K,V>[] tab;
    Node<K,V> first, e;
    int n;
    K k;
    if ((tab = table) != null && (n = tab.length) > 0 &&
            (first = tab[(n - 1) & hash]) != null) {
        // 如果第一个节点就是要查找的节点，则直接返回
        if (first.hash == hash && ((k = first.key) == key || (key != null && key.equals(k))))
            return first;
        // 如果第一个节点不是要查找的节点，则遍历节点链表查找
        if ((e = first.next) != null) {
            do {
                if (e.hash == hash && ((k = e.key) == key || (key != null && key.equals(k))))
                    return e;
            } while ((e = e.next) != null);
        }
    }
    // 如果节点链表中没有找到对应的节点，则返回 null
    return null;
}
```

## 2. HashMap的扩容原理

### 1. resize机制

jdk8引入了红黑树，链表长度大于16会将链表转化为红黑树以此来优化查询效率，但是对于我这样的菜鸡，教程说可能会比较难理解(==可能？比较？==)，这里就还用的是jdk7的源码

```java
// jdk7
// newCapacity为新的容量
void resize(int newCapacity) {
    // 小数组，临时过度下
    Entry[] oldTable = table;
    // 扩容前的容量
    int oldCapacity = oldTable.length;
    // MAXIMUM_CAPACITY 为最大容量，2 的 30 次方 = 1<<30
    if (oldCapacity == MAXIMUM_CAPACITY) {
        // 容量调整为 Integer 的最大值 0x7fffffff（十六进制）=2 的 31 次方-1
        threshold = Integer.MAX_VALUE;
        return;
    }

    // 初始化一个新的数组（大容量）
    Entry[] newTable = new Entry[newCapacity];
    // 把小数组的元素转移到大数组中
    transfer(newTable, initHashSeedAsNeeded(newCapacity));
    // 引用新的大数组
    table = newTable;
    // 重新计算阈值
    threshold = (int)Math.min(newCapacity * loadFactor, MAXIMUM_CAPACITY + 1);
}
```

该方法首先会创建一个小`Entry`数组，然后获取扩容前的容量，如果就容量已经等于最大容量`MAXIMUM_CAPACITY`，那就将容量调整为Integer的最大值，也就是2^31 - 1

之后初始化一个新的大数组，使用`transfer`将小数组的元素转移到大数组上，之后再引入新的大数组，最后重新计算阈值，取`MAXIMUM_CAPACITY + 1`和`newCapacity * loadFactory`之间的较小值，再转成`int`。

### 3. transfer方法

```java
void transfer(Entry[] newTable, boolean rehash) {
    // 新的容量
    int newCapacity = newTable.length;
    // 遍历小数组
    for (Entry<K,V> e : table) {
        while(null != e) {
            // 拉链法，相同 key 上的不同值
            Entry<K,V> next = e.next;
            // 是否需要重新计算 hash
            if (rehash) {
                e.hash = null == e.key ? 0 : hash(e.key);
            }
            // 根据大数组的容量，和键的 hash 计算元素在数组中的下标
            int i = indexFor(e.hash, newCapacity);

            // 同一位置上的新元素被放在链表的头部
            e.next = newTable[i];

            // 放在新的数组上
            newTable[i] = e;

            // 链表上的下一个元素
            e = next;
        }
    }
}
```

该方法接受一个新的`Entry`数组，以及一个boolean，表示是否需要重新计算键的哈希值，然后获取新`Enrty`数组的长度，再遍历小数组，对于每个`Entry`，使用拉链法将key相同的每个值存在一个链表中，如果需要重新计算哈希值，那么就将新的哈希值存储在`Entry的hash数组中`

接着根据大数组的长度和键的哈希值计算元素在数组中的下标，之后使用头插法将新元素放在链表的头部

### 4. 拉链法

```java
e.next = newTable[i];
newTable[i] = e;
```

这就是典型的头插法，会导致第一个放在该位置上的元素最终会到链表的尾部，也会导致旧数组中一个链表中的元素，通过重新计算索引之后被放到了不同的位置

为了解决这个问题，jdk8做了很大的优化：

```java
final Node<K,V>[] resize() {
    Node<K,V>[] oldTab = table; // 获取原来的数组 table
    int oldCap = (oldTab == null) ? 0 : oldTab.length; // 获取数组长度 oldCap
    int oldThr = threshold; // 获取阈值 oldThr
    int newCap, newThr = 0;
    if (oldCap > 0) { // 如果原来的数组 table 不为空
        if (oldCap >= MAXIMUM_CAPACITY) { // 超过最大值就不再扩充了，就只好随你碰撞去吧
            threshold = Integer.MAX_VALUE;
            return oldTab;
        }
        else if ((newCap = oldCap << 1) < MAXIMUM_CAPACITY && // 没超过最大值，就扩充为原来的2倍
                 oldCap >= DEFAULT_INITIAL_CAPACITY)
            newThr = oldThr << 1; // double threshold
    }
    else if (oldThr > 0) // initial capacity was placed in threshold
        newCap = oldThr;
    else { // zero initial threshold signifies using defaults
        newCap = DEFAULT_INITIAL_CAPACITY;
        newThr = (int)(DEFAULT_LOAD_FACTOR * DEFAULT_INITIAL_CAPACITY);
    }
    // 计算新的 resize 上限
    if (newThr == 0) {
        float ft = (float)newCap * loadFactor;
        newThr = (newCap < MAXIMUM_CAPACITY && ft < (float)MAXIMUM_CAPACITY ?
                  (int)ft : Integer.MAX_VALUE);
    }
    threshold = newThr; // 将新阈值赋值给成员变量 threshold
    @SuppressWarnings({"rawtypes","unchecked"})
        Node<K,V>[] newTab = (Node<K,V>[])new Node[newCap]; // 创建新数组 newTab
    table = newTab; // 将新数组 newTab 赋值给成员变量 table
    if (oldTab != null) { // 如果旧数组 oldTab 不为空
        for (int j = 0; j < oldCap; ++j) { // 遍历旧数组的每个元素
            Node<K,V> e;
            if ((e = oldTab[j]) != null) { // 如果该元素不为空
                oldTab[j] = null; // 将旧数组中该位置的元素置为 null，以便垃圾回收
                if (e.next == null) // 如果该元素没有冲突
                    newTab[e.hash & (newCap - 1)] = e; // 直接将该元素放入新数组
                else if (e instanceof TreeNode) // 如果该元素是树节点
                    ((TreeNode<K,V>)e).split(this, newTab, j, oldCap); // 将该树节点分裂成两个链表
                else { // 如果该元素是链表
                    Node<K,V> loHead = null, loTail = null; // 低位链表的头结点和尾结点
                    Node<K,V> hiHead = null, hiTail = null; // 高位链表的头结点和尾结点
                    Node<K,V> next;
                    do { // 遍历该链表
                        next = e.next;
                        if ((e.hash & oldCap) == 0) { // 如果该元素在低位链表中
                            if (loTail == null) // 如果低位链表还没有结点
                                loHead = e; // 将该元素作为低位链表的头结点
                            else
                                loTail.next = e; // 如果低位链表已经有结点，将该元素加入低位链表的尾部
                            loTail = e; // 更新低位链表的尾结点
                        }
                        else { // 如果该元素在高位链表中
                            if (hiTail == null) // 如果高位链表还没有结点
                                hiHead = e; // 将该元素作为高位链表的头结点
                            else
                                hiTail.next = e; // 如果高位链表已经有结点，将该元素加入高位链表的尾部
                            hiTail = e; // 更新高位链表的尾结点
                        }
                    } while ((e = next) != null); //
                    if (loTail != null) { // 如果低位链表不为空
                        loTail.next = null; // 将低位链表的尾结点指向 null，以便垃圾回收
                        newTab[j] = loHead; // 将低位链表作为新数组对应位置的元素
                    }
                    if (hiTail != null) { // 如果高位链表不为空
                        hiTail.next = null; // 将高位链表的尾结点指向 null，以便垃圾回收
                        newTab[j + oldCap] = hiHead; // 将高位链表作为新数组对应位置的元素
                    }
                }
            }
        }
    }
    return newTab; // 返回新数组
}
```

## 3. 加载因子为什么是0.75？

HashMap是通过数组 + 链表/红黑树实现的，要往HashMap中添加数据或者取数据时，就需要确定数组在数组中的下标(索引)

先把数据的键进行一次hash：

```java
static final int hash(Object key) {
    int h;
    return (key == null) ? 0 : (h = key.hashCode()) ^ (h >>> 16);
}
```

再做一次取模运算确定下标

```java 
i = (n - 1) & hash
```

这样就容易产生两个问题：
- 数组容量过小，很容易出现哈希冲突
- 数组容量过大，利用率不够

加载因子是用来表示HashMap中数据的填满程度的：

> 加载因子 = 填入哈希表中的数据个数 / 哈希表的长度

也就是说：
- 加载因子小，利用率不高，填的数据少，哈希冲突的概率也小
- 加载因子大，利用率高，但数据多，发生哈希冲突的概率也更大

也就是必须在哈希冲突和空间利用率之间取得一个平衡

为了减少哈希冲突发生的概率，当HashMap中的数组长度达到一个临界值的时候，就会触发扩容操作，将原来的小数组中的元素转移到大数组中，这是一个相当耗时的操作

==临界值 = 加载因子 * 初始容量==

一开始，HashMap的容量是16，加载因子是0.75，即数组长度为12时，触发扩容，那为什么不是其他的值？

这跟统计学上的泊松原理有关([泊松分布和指数分布：10分钟教程 - 阮一峰的网络日志](https://www.ruanyifeng.com/blog/2015/06/poisson-distribution.html)看吧你就看吧，一看一个不吱声)

翻译：
```txt
因为TreeNode（红黑树的节点）的大小大约是常规节点（链表的节点 Node）的两倍，所以只有当桶内包含足够多的节点时才使用红黑树（参见TREEIFY_THRESHOLD「阈值，值为8」，节点数量较多时，红黑树可以提高查询效率）。

在具有良好分布的hashCode使用中，很少使用红黑树。
```

这段话本意更多的是表示为什么jdk8中拉链长度超过8时进行了红黑树转换，但提到了0.75这个加载因子，但没提到为什么

想要搞清楚，见[【JAVA】HashMap的负载因子为什么是0.75 - 个人文章 - SegmentFault 思否](https://segmentfault.com/a/1190000023308658)
里面提到了高中时学过的`二项分布`，即：
```txt
在做一件事情的时候，其结果的概率只有 2 种情况，和抛硬币一样，不是正面就是反面。

假如，我们做了 N 次实验，那么在每次试验中只有两种可能的结果，并且每次实验是独立的，不同实验之间互不影响，每次实验成功的概率都是一样的。
```

以此理论为基础，往哈希表中扔数据，如果发生哈希冲突就失败，否则成功

假设实验的每个哈希值是随机的，并且经过哈希运算的键都会映射到哈希表的地址空间上，那么这个结果也是随机的。所以每次`put`的时候就相当于在扔一个16面(HashMap第一次扩容后的数组长度为16)的骰子，扔骰子的实验肯定是相互独立的，碰撞发生就是出现了重复数字

实验目的呢？

就是投掷k次骰子，没有一次是相同的概率(即在之前实验的基础上，再投骰子，那么发生冲突的概率就会变化，因为原来实验的桶已经被占了)，需要不发生哈希冲突的概率尽可能的大些，一般情况下要 > 0.5(理想数)

考虑到HashMap的容量必须是2的n次方，那么选择0.75则保证了容量与负载因子的乘积为整数。

除了0.75，0.5~1之间还可选0.625，0.875，从中位数的角度来看，选0.75比较完美

另外维基百科上还提到，拉链法的加载因子最好限制在0.7~0.8以下，超过0.8时，查表时的CPU缓存不命中会按照指数曲线上升

一句话总结：负载因子 = 填入哈希表中数据的个数 / 哈希表的长度，如果太低，空间利用率低，如果太高，那么发生哈希冲突的概率又太大，因此需要一个能折中的数值，就是0.75

为什是0.75呢？这是根据结合统计学原理 + 数学公式推导出来的。

以第一次扩容后的长度为例，也就是16，把每次计算键的哈希值当作一次独立的二项分布实验，那么根据公式，n次实验，碰撞为0，也就是概率为0，可以得到一个等式(算出来结果是下方左边)，需要大于0.5，这是一个理想值，根据这个计算出加载因子大概等于0.693，由于长度是2的n次方，要满足负载因子 * 容量是整数，因此就选择了0.75
$$
\left(1 - \frac{1}{s}\right)^n \ge \frac{1}{2}
$$
