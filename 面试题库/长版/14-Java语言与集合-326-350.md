# Java 语言与集合（326-350）

## 326. 面向对象三大特性怎么理解？

### 面试时可以这样答

> 封装把状态和合法操作放在一起，外部不能随意破坏不变量；继承表达 is-a 并复用实现，但会形成紧耦合；多态让调用方依赖接口，运行时选择具体实现。三者不是背定义，核心是控制变化。
>
> 工程中我更偏向组合加接口。继承只在子类确实能替代父类、共享约束稳定时使用，避免为了复用几行代码制造脆弱层级。

## 327. 重载与重写有什么区别？

### 面试时可以这样答

> 重载发生在同一类型或继承范围内，方法名相同、参数列表不同，编译期根据静态类型选择；重写是子类提供相同签名的实例方法，运行时按实际对象动态分派。
>
> 返回类型不能单独构成重载。重写可以协变返回类型，访问权限不能更窄，受检异常范围也不能更宽。static 方法是隐藏，不是运行时重写。

## 328. `equals` 与 `hashCode` 为什么必须一起重写？

### 面试时可以这样答

> 约定要求 equals 相等的对象必须有相同 hashCode。HashMap 先按 hash 定位桶，再比较 equals；只改 equals 会让逻辑相等对象落到不同桶，get 和去重失败。
>
> 反过来，相同 hashCode 不要求 equals 相等，碰撞由桶内比较解决。作为 key 的字段在放入 Map 后不应变化，否则对象会留在旧桶位置。

## 329. String 为什么不可变？

### 面试时可以这样答

> String 内部值不向外暴露，所有看似修改的方法都返回新对象。不可变让字符串可安全共享、缓存 hash、放入字符串常量池，也适合作为类名、路径和安全参数。
>
> 不可变指 String 对象本身，变量仍可指向另一字符串。大量拼接应使用 StringBuilder，避免中间对象和重复复制。

## 330. `StringBuilder` 与 `StringBuffer` 怎么选？

### 面试时可以这样答

> 两者都维护可变字符序列。StringBuffer 的核心方法带同步，StringBuilder 不同步，单线程局部拼接通常选后者。线程安全不能只看类名，多步组合操作即使用 StringBuffer 也可能需要外部同步。
>
> 编译器会优化简单的 `+` 拼接，但循环中不断 `result += x` 仍可能反复创建对象。

## 331. Integer 缓存有什么常见坑？

### 面试时可以这样答

> `Integer.valueOf` 默认缓存 -128 到 127，因此这个范围内两个装箱结果可能 `==`，范围外通常不是同一引用。`==` 混合基本类型时还可能触发拆箱。
>
> 业务比较包装类型用 equals，并先处理 null。不要依赖缓存范围，它是实现优化，不是数值相等语义。

## 332. Java 是值传递还是引用传递？

### 面试时可以这样答

> Java 始终值传递。基本类型传值本身，对象参数传的是引用值的副本。方法可以通过这个副本修改同一对象内部状态，却不能让调用方变量改指另一个对象。
>
> 说“对象按引用传递”容易混淆，因为真正的引用传递应允许被调方法替换调用方引用。可以用交换两个对象参数的例子验证：方法内交换副本，调用方两个变量仍指向原对象。

## 333. checked 与 unchecked exception 怎么用？

### 面试时可以这样答

> checked exception 强迫调用方处理或声明，适合调用方有明确恢复动作的外部失败；RuntimeException 常表示参数错误、状态不变量被破坏或难以就地恢复。业务错误也可用明确结果类型表达。
>
> 不要 catch Exception 后返回 null，也不要层层原样包装丢失根因。转换异常时保留 cause，并在边界统一映射对外错误。

## 334. try-with-resources 如何工作？

### 面试时可以这样答

> 实现 AutoCloseable 的资源会在代码块退出时按声明逆序关闭，包括正常返回和异常。若业务代码与 close 都抛异常，业务异常为主，关闭异常进入 suppressed。
>
> JDBC Connection、Statement、ResultSet 都应使用它。只关闭外层对象是否连带关闭内层依赖驱动行为，显式管理更清楚。

## 335. 泛型解决了什么问题？

### 面试时可以这样答

> 泛型把元素类型约束前移到编译期，减少强转，并让集合和算法复用。`List<String>` 取值直接是 String，错误插入在编译时被拒绝。
>
> Java 泛型主要通过擦除实现，运行时通常不知道具体参数，因此不能直接 `new T()`、`instanceof List<String>` 或创建泛型数组。

## 336. 什么是 PECS？

### 面试时可以这样答

> Producer Extends，Consumer Super。只从集合读取 T 时用 `? extends T`，可以接收 T 的子类型集合；向集合写入 T 时用 `? super T`。`List<? extends Number>` 不能安全 add Integer，因为实际列表可能是 List<Double>。
>
> PECS 用在 API 边界提高灵活性，内部局部变量不必到处使用通配符。

## 337. 为什么数组协变而泛型不协变？

### 面试时可以这样答

> `String[]` 可以赋给 `Object[]`，但写入 Integer 会在运行时抛 ArrayStoreException。`List<String>` 不能赋给 `List<Object>`，否则同样会允许插入错误类型；泛型把问题挡在编译期。
>
> 需要只读协变时使用 `List<? extends Object>`，但不能安全写入具体对象。

## 338. 反射的用途和代价是什么？

### 面试时可以这样答

> 反射在运行时读取类、方法、字段和注解，框架用它做依赖注入、序列化和插件发现。代价包括编译期检查变弱、调用更慢、模块访问限制以及重构不透明。
>
> 业务代码不应为普通调用使用反射。框架边界可缓存元数据，并把反射异常转成明确配置错误。原生镜像或强模块环境还需要显式声明反射可达性，不能假设所有成员始终可访问。

## 339. 注解本身会执行逻辑吗？

### 面试时可以这样答

> 注解只是元数据。是否在运行时可见由 Retention 决定，作用位置由 Target 决定。真正逻辑由编译器、注解处理器、反射代码或 Spring AOP 等读取者执行。
>
> 自定义注解若没有配套处理器，只是贴了标签。面试时应能指出谁读取、在什么时机读取，以及注解放在接口、实现类或代理方法上时读取位置是否一致。

## 340. ArrayList 的扩容机制是什么？

### 面试时可以这样答

> ArrayList 底层是连续 Object 数组。容量不足时创建更大数组并复制元素，当前 JDK 常按约 1.5 倍增长，但面试重点是均摊 O(1) 追加和扩容复制，不应把实现常量当永久规范。
>
> 已知规模时设置初始容量可减少复制。中间插入和删除需要移动元素，是 O(n)。

## 341. LinkedList 为什么通常不比 ArrayList 快？

### 面试时可以这样答

> LinkedList 在已知节点处插入删除是 O(1)，但按下标找到节点仍是 O(n)。每个节点还有前后引用和对象开销，缓存局部性也差。ArrayList 的数组移动由底层批量复制，实际常更快。
>
> 队列场景通常选 ArrayDeque。只有频繁迭代定位后插删且确有性能证据时再考虑 LinkedList。

## 342. HashMap 的 put 流程是什么？

### 面试时可以这样答

> 先扰动 hash，根据容量定位桶；桶为空直接放入，否则比较 hash 与 equals，命中则替换，未命中追加到链表或树。元素数超过阈值后扩容，链表在容量和长度达到条件时树化。
>
> 平均查询接近 O(1)，碰撞严重时退化。好的 hashCode、不可变 key 和合理容量比死背树化常量更重要。

## 343. HashMap 为什么容量通常是 2 的幂？

### 面试时可以这样答

> 桶下标可以用 `(n - 1) & hash` 代替取模，低位分布充分时更快。扩容翻倍后，元素要么留在原位置，要么移动旧容量的偏移，迁移计算也更简单。
>
> 这依赖 hash 扰动减少高位信息浪费。容量规则是实现细节，但能解释性能设计。初始容量还应结合负载因子估算，避免插入不久就扩容，也不要为少量元素预留巨大数组。

## 344. HashMap 为什么线程不安全？

### 面试时可以这样答

> 并发 put、resize 和结构修改没有同步，可能丢更新、读取到不一致状态，迭代也会 fail-fast。即使只做“先判断再写入”，多个线程也会破坏复合操作原子性。
>
> 并发访问用 ConcurrentHashMap，或在更高层加锁。`Collections.synchronizedMap` 只同步单个方法，迭代仍需外部锁。

## 345. ConcurrentHashMap 为什么不允许 null？

### 面试时可以这样答

> 并发环境下 `get(key) == null` 无法区分 key 不存在还是 value 就是 null，而且两次 contains 与 get 之间状态可能变化。禁止 null 后，null 可以稳定表示未找到。
>
> HashMap 允许一个 null key 和多个 null value，但业务上也应避免用 null 混淆缺失语义。

## 346. HashSet 如何实现？

### 面试时可以这样答

> HashSet 内部使用 HashMap，集合元素作为 key，value 是共享占位对象。去重与查找因此依赖元素的 hashCode 和 equals。
>
> 可变对象放入后若参与 hash 的字段改变，remove 和 contains 可能找不到它。集合元素最好具有稳定值语义。

## 347. TreeMap 适合什么场景？

### 面试时可以这样答

> TreeMap 基于红黑树，按自然顺序或 Comparator 排序，get、put、remove 是 O(log n)，还支持范围查询、floor、ceiling。需要有序 key 和邻近查找时适合。
>
> Comparator 必须与 equals 语义协调。比较结果为 0 的两个 key 会被视为同一个映射项，即使 equals 不相等。

## 348. fail-fast 迭代器是什么？

### 面试时可以这样答

> 集合记录结构修改次数，迭代器发现与创建时不一致会尽力抛 ConcurrentModificationException，帮助暴露错误修改。它不是线程安全保证，也不承诺在所有竞态下必然抛出。
>
> 单线程遍历删除使用 Iterator.remove；并发场景选择并发集合或快照，而不是捕获异常继续。

## 349. Stream 与集合有什么区别？

### 面试时可以这样答

> 集合存储数据，Stream 描述一次计算流水线，通常惰性执行，终止操作触发处理。Stream 不能重复消费，操作应避免修改外部状态，才能安全优化或并行。
>
> 简单循环往往更易读。并行流使用公共 ForkJoinPool，不适合随意包住阻塞 I/O 或放在服务端共享环境。

## 350. Optional 应该用在哪里？

### 面试时可以这样答

> Optional 适合作为返回值明确表示可能缺失，让调用方使用 map、orElseGet 或 orElseThrow。实体字段、方法参数和序列化 DTO 中使用往往增加框架兼容和嵌套复杂度。
>
> `orElse` 会提前计算默认值，昂贵回退使用 `orElseGet`。不要调用 get 前再忘记检查。
