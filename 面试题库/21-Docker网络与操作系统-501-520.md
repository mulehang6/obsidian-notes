# Docker、网络与操作系统（501-520）

## 501. 容器和虚拟机有什么区别？

### 面试时可以这样答

> 虚拟机通过虚拟化硬件运行完整客体操作系统，隔离边界较强但启动和资源成本较高；容器共享宿主机内核，用 namespace 隔离视图、cgroup 限制资源，以镜像提供用户态文件系统，因此更轻量。
>
> 容器不是迷你虚拟机，也不是绝对安全边界。内核漏洞、过高权限和挂载宿主目录都可能突破隔离，生产环境仍要最小权限、资源限制和镜像治理。

## 502. Docker 镜像和容器是什么关系？

### 面试时可以这样答

> 镜像是只读分层模板，包含运行应用所需文件和元数据；容器是镜像的一个运行实例，在只读层上增加可写层并配置进程、网络和挂载。同一镜像可启动多个相互隔离的容器。
>
> 容器删除后可写层通常随之消失，因此业务数据必须放卷或外部存储。把线上手工修改容器当成发布方式会造成不可复现的状态漂移。

## 503. 镜像分层有什么价值和代价？

### 面试时可以这样答

> 每条构建指令形成可复用层，多个镜像和构建过程可共享缓存，降低分发与重复构建成本。容器运行时通过联合文件系统呈现统一视图。
>
> 层是不可变的，在后一层删除文件不会从早期层抹去其体积。Dockerfile 应把变化少的依赖步骤放前面、频繁变化的源码放后面，并用 `.dockerignore` 控制构建上下文。

## 504. 为什么使用多阶段构建？

### 面试时可以这样答

> 在 builder 阶段安装编译器和依赖完成构建，再把产物复制到精简运行阶段。最终镜像不包含源码、缓存和构建工具，因此体积更小、攻击面也更低。
>
> 对 Java 应用仍要选择兼容的 JRE、证书和时区数据，并确认容器内诊断工具需求。镜像小不是唯一目标，可调试性和供应链可追溯同样重要。

## 505. ENTRYPOINT 和 CMD 有什么区别？

### 面试时可以这样答

> ENTRYPOINT 通常定义容器的主程序，CMD 提供默认命令或参数，运行时传入参数会覆盖 CMD；两者组合可形成固定程序加可替换参数。JSON exec 形式能让主进程直接接收信号。
>
> shell 形式可能多一层 shell，影响信号转发和优雅退出。应用应作为 PID 1 正确处理 SIGTERM，并回收子进程，不能靠强制 kill 完成发布。

## 506. Docker volume 和 bind mount 怎么选？

### 面试时可以这样答

> volume 由 Docker 管理路径和生命周期，跨平台体验较稳定，适合数据库等持久数据；bind mount 把明确的宿主路径映射进容器，开发时挂源码方便，但更耦合宿主目录结构和权限。
>
> 生产中避免把敏感宿主目录广泛可写挂载。无论哪种方式，挂载都不是备份，仍要做一致性快照、恢复演练和权限控制。

## 507. Docker bridge 网络如何通信？

### 面试时可以这样答

> 同一用户自定义 bridge 网络中的容器可通过内置 DNS 用服务名互相访问；访问外部通常经过宿主转发与 NAT。端口发布把宿主端口映射到容器端口，主要用于网络外部访问。
>
> 容器之间通信不应写死临时 IP。`EXPOSE` 主要是元数据说明，不等于自动把端口开放到宿主机。

## 508. 容器健康检查和进程存活有什么区别？

### 面试时可以这样答

> 进程存在只说明 PID 还在，健康检查可以验证应用是否能服务，例如 HTTP 健康端点、依赖初始化状态。检查可配置间隔、超时、重试和启动宽限期。
>
> 健康端点不能做昂贵全链路查询，否则检查本身会制造负载。存活与就绪最好区分：不可恢复才重启，暂时未就绪则停止接流量。

## 509. 为什么要给容器设置资源限制？

### 面试时可以这样答

> CPU、内存和 PID 若不限制，单个异常容器可能挤压整台宿主机。cgroup 限制让调度和故障域更可控，但达到内存上限可能触发 OOM kill，CPU 限制则可能表现为节流和高延迟。
>
> Java 进程要让堆、直接内存、线程栈和 native 开销共同留在容器预算内。只把 `-Xmx` 设成容器内存上限会没有安全余量。

## 510. Docker Compose 适合什么场景？

### 面试时可以这样答

> Compose 用声明文件定义多容器服务、网络、卷和环境配置，适合本地开发、集成测试和单机部署。它能把 MySQL、Redis、ES 与应用的一组启动条件版本化。
>
> `depends_on` 的启动顺序不自动等于依赖已可用，应配健康检查和应用重试。大规模跨节点调度、滚动发布和自动恢复通常需要专门编排平台。

## 511. TCP 三次握手为什么不是两次？

### 面试时可以这样答

> 双方需要确认各自的发送和接收能力，并交换初始序列号。第三次 ACK 让服务端确认客户端已收到服务端的 SYN 和序列号，也避免历史失效连接请求让服务端误以为连接已建立。
>
> 握手建立的是可靠字节流的状态，不代表应用鉴权或 TLS 已完成。连接延迟还可能包含 DNS、TCP、TLS 和应用协议多个阶段。

## 512. TCP 四次挥手为什么常见 TIME_WAIT？

### 面试时可以这样答

> TCP 两个方向独立关闭，主动关闭方发送 FIN，对方 ACK 后仍可发送剩余数据，随后对方 FIN，主动方再 ACK。主动方进入 TIME_WAIT，等待旧报文消失并可重发最终 ACK。
>
> 大量 TIME_WAIT 不一定是故障，它常说明频繁短连接。应优先使用连接复用、池化和合理 keep-alive，而不是随意缩短内核时间破坏协议安全边界。

## 513. TCP 如何保证可靠传输？

### 面试时可以这样答

> 通过序列号、确认、校验、超时重传、快速重传、滑动窗口和拥塞控制，TCP 向应用提供有序、不重复的字节流。接收窗口做流量控制，拥塞窗口保护网络，两者共同限制发送量。
>
> TCP 的可靠只到对端协议栈，不等于对方业务已处理或落盘。应用仍需响应语义、超时、幂等和重试边界。

## 514. HTTP 和 HTTPS 的核心区别是什么？

### 面试时可以这样答

> HTTPS 是 HTTP 运行在 TLS 保护之上，提供传输加密、完整性校验和基于证书的服务端身份认证。它防止中间人直接读取或篡改内容，但不保证服务端业务本身可信。
>
> 正确部署还包括证书链、主机名验证、安全协议版本和密钥保护。跳过证书校验会让“加密连接”失去身份认证，仍可能被中间人攻击。

## 515. 一次 HTTPS 请求大致经历什么？

### 面试时可以这样答

> 通常先 DNS 解析，再建立 TCP 连接，进行 TLS 握手协商版本、密码套件并验证证书，随后在加密通道传输 HTTP 请求与响应。连接复用、会话恢复和 HTTP/2、HTTP/3 会改变部分往返。
>
> 性能排查应分解 DNS、连接、TLS、首字节和下载时间。只看总耗时无法判断是网络、服务器处理还是连接池问题。

## 516. HTTP/1.1、HTTP/2 和 HTTP/3 有何主要差异？

### 面试时可以这样答

> HTTP/1.1 常靠多个 TCP 连接并发；HTTP/2 在一个 TCP 连接上多路复用二进制流并压缩头部，但底层丢包仍可能阻塞所有流；HTTP/3 基于 QUIC/UDP，让不同流的丢包影响更隔离，并集成 TLS。
>
> 协议升级收益取决于网络、代理链和资源模式。应用层仍要控制请求数、负载大小与缓存，不能指望协议自动修复慢查询。

## 517. Cookie、Session 和 Token 如何理解？

### 面试时可以这样答

> Cookie 是浏览器携带的小段客户端状态；Session 通常用 Cookie 中的会话 ID 关联服务端状态；Token 是自包含或可查询的授权凭据，可放在 Authorization 头。三者是不同层面的概念，不是互斥技术名词。
>
> 浏览器认证要考虑 HttpOnly、Secure、SameSite、CSRF 和 XSS。JWT 难以即时撤销且体积较大，不应因为“无状态”就默认优于服务端会话。

## 518. 进程切换与线程切换的成本来自哪里？

### 面试时可以这样答

> 切换需要保存恢复寄存器和调度状态，并可能扰动 CPU 缓存、TLB 与分支预测。不同进程地址空间隔离更强，切换通常涉及更多内存映射影响；同进程线程共享地址空间但仍不是零成本。
>
> 性能问题不能只看线程数量，应观察运行队列、上下文切换率、阻塞原因和 CPU 利用率。大量等待型线程与大量可运行线程的含义完全不同。

## 519. 用户态和内核态为什么要区分？

### 面试时可以这样答

> 用户程序受限执行，访问文件、网络和硬件等特权资源要通过系统调用进入内核，由内核校验权限和管理共享资源。这一边界提高隔离与稳定性，但切换和数据复制可能产生开销。
>
> 零拷贝、批量系统调用和异步 I/O 都在减少边界往返或复制。优化前要用 profiling 确认瓶颈，不能因为“系统调用贵”就绕开正确抽象。

## 520. 线上服务 CPU 飙高如何排查？

### 面试时可以这样答

> 先确认是单实例还是全局、用户态还是内核态、持续还是突发；再定位高 CPU 进程和线程，把线程 ID 对应到 JVM dump/JFR 栈，检查热点循环、GC、锁自旋、序列化和异常风暴。
>
> 同时关联发布、流量和依赖变化。限流或扩容可以止血，但最终要用采样证据定位代码路径，并在修复后对相同负载复测 CPU 与尾延迟。
