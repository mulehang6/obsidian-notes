# 简历聚焦版面试题库

这套题库只服务于当前简历。目标是把简历上的每一句话讲清楚，不做通用八股百科。

## 这版保留什么

### Mulehang Agent

简历上写了三条主线：

1. Koog Graph-based Agent 的 ReAct 循环、最大迭代次数、Hooks 和项目级 Guidelines。
2. SQLite 任务快照、运行状态、Schema 迁移、迁移前备份和进程重启后的状态恢复。
3. 参考 Pi 的树状 Session，支持历史节点分支、上下文切换和会话回溯。

### 技术交流平台

简历上写了四条主线：

1. Redis 热点文章缓存和排行榜统计。
2. Elasticsearch 文章全文检索与关键词、标签、作者等条件组合查询。
3. AOP + MDC 记录请求标识和耗时，用于排查问题与链路追踪。
4. RabbitMQ 解耦部分异步流程，减少主流程阻塞。

### 技能区

只保留面试中最容易被验证、又能回扣项目的基础题：Java/Kotlin 集合与并发、Spring IoC/AOP、MySQL 事务与索引、Redis 缓存、Elasticsearch、RabbitMQ、Kotlin 协程和 Compose Desktop。

## 每道题怎么练

先看“第一句回答”，要求 20 秒内说清结论。然后补“展开结构”，把场景、方案、代价和验证说完整。最后遮住答案，只看“追问方向”，练习把回答拉回自己真正做过的事情。

每道题都按下面的顺序组织：

1. 先说结论。
2. 说明项目场景和约束。
3. 讲清数据流或状态变化。
4. 交代失败路径和取舍。
5. 说出当前实现的边界。

## 需要主动校准的两处简历表述

### “项目级 Guidelines”

当前代码已经能证明运行时资源中的 `systemPromptAppendix` 会追加到 Agent 的 system prompt，项目指令发现也有信任门槛。面试时可以说“项目级指令会进入本轮资源快照并追加到 system prompt”，不要把它说成模型天然理解仓库规范，也不要把 `AGENTS.md` 文件名本身当成实现。

### “标签组合查询”

当前 ES 搜索主链路能明确证明关键词、标题、正文、作者和栏目等条件会组成 `bool.must` 与 `bool.filter`。文章标签在项目里有独立的 MySQL 关联查询路径。若面试官追问“标签是否直接作为 ES filter”，应如实区分当前实现，不要把所有文章筛选都说成同一条 ES 查询。

## 证据原则

题库里的代码路径只用于复盘和验证，不用于背包名、类名和函数名。面试官通常更关心：为什么这样拆、数据谁是权威、失败后怎么办、如何证明它有效。

当前版本保留旧题库，不删除原有 540 题。以后如果这套内容稳定，再把旧题库中确实有用的题迁入这里。
