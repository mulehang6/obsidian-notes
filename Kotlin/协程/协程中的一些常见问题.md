# 0. 一些必备的基础概念
## 1. continuation。中文一般叫“续体”。
例：
```java
void work() {
    System.out.println("A");
    doSomething();
    System.out.println("B");
}
```

现在假设 `doSomething()` 要等待服务器响应，可能需要 10 秒。
传统同步写法会让当前线程一直等待。

而协程希望做到：
1. 先打印 A。
2. 遇到等待操作，把当前任务挂起。
3. 线程去处理其他任务。
4. 服务器返回结果后，再从原来的位置继续执行，打印 B。
问题来了：线程都去干别的了，程序怎么记住自己执行到哪里？
continuation 就是干这个的

## 3. Job
kotlin 协程库里负责跟踪任务生命周期的接口

可以先理解为一个"任务管理对象"。
例如：
```kotlin
val job = scope.launch {
    delay(5000)
    println("完成")
}
```
`launch` 返回的就是 `Job`。

可以用这个对象管理任务：
```kotlin
job.cancel() // 请求取消
job.join()   // 挂起等待任务结束
```

也能查看任务状态：
```kotlin
job.isActive
job.isCancelled
job.isCompleted
```

Job 和协程的区别
- 协程是实际执行的计算任务。
- Job 管理任务的生命周期、完成状态、取消及父子关系。

一个由 `launch` 启动的协程通常有对应的 Job，所以平时常把"父协程"与"父 Job"放在一起说。

但它们不是完全相同的概念，因为 Job 可以单独创建：
```kotlin
val parentJob = Job()

val scope = CoroutineScope(
    parentJob + Dispatchers.Default
)
```
这里 `parentJob` 本身没有运行任何代码，却能作为作用域的父 Job，管理之后启动的子协程。

举个异常传播的例子
```kotlin
fun main() = runBlocking {
	//因为这里是 runBlocking的子协程，因此这个抛异常会导致父 Job 也取消，进而影响下面的 launch 协程 
    coroutineScope {
        launch {
            delay(100) // 注意这里是 0.1 秒，而下面是 5 秒
            throw RuntimeException("A 出错了")
        }

        launch {
            try {
                delay(5000)
                println("B 完成")
            } finally {
                println("B 被清理")
            }
        }
    }
}
```

正常情况下：

1. A 在 100 毫秒后抛出异常。
2. A 的失败导致当前普通 `coroutineScope` 进入取消流程。
3. B 也被取消，因此不会打印"B 完成"。
4. B 的 `finally` 执行，打印"B 被清理"。
5. 异常继续从 `coroutineScope` 向调用方抛出。

但注意，主动 `job.cancel()` 和任务因为普通异常而失败并不相同。正常取消一个子任务，不会默认连带取消父任务。
这就是为什么 Kotlin 需要区分取消和失败。

# 1. 父协程取消了，子协程呢？
正常的父子Job关系下，取消信息会向下传递，因此子协程也会被取消

# 2. 子协程异常，其他兄弟协程呢？
默认情况下，一个子协程因为非取消异常失败，通常会直接取消父Job。

但是`SupervisorJob` 和 `supervisorScope` 可以隔离直接子任务之间的失败传播

# 3. 协程的状态机是谁生成的？会保存哪些东西？如何恢复？是不是每个suspend函数都会真正挂起？
1. 协程状态机由kotlin编译器生成
2. 会保存执行状态，以及后面执行还需要的局部变量等信息
3. 异步操作完成后，通过 continuation 的恢复机制继续执行对应状态，调度器参与安排运行
4. 不是。suspend表示允许挂起，不代表每次调用都挂起
