# 1. 进程

## 1.1 定义：什么是进程？

**进程就是一个正在运行的程序实例**

例如写了个 Spring Boot 程序，打成 jar 包 `app.jar`，然后执行：
```bash
java -jar app.jar
```
操作系统就会启动一个 Java 进程。

这个进程有自己的资源，如：<mark style="background-color: #FFB86CA6;">(肯定记不住的，看看得了)</mark>
- 虚拟地址空间，用于存放代码、堆、栈等数据。
- 操作系统分配和管理的资源，例如打开的文件、网络连接。
- 一个或多个执行代码的线程。
不同进程默认互相隔离，不能随意访问对方的内存

# 2. 线程

## 2.1 定义：什么是线程？

**线程是操作系统进行 CPU 调度的基本单位，也是进程内部执行代码的单位。**

一个进程可以包含多个线程，例如一个 Spring Boot 项目同时收到两个 HTTP 请求：
- A：查询用户信息
- B：查询文章列表
如果只有一个执行线程，两个请求通常需要排队处理。如果有多个执行线程，那就可以每个线程处理一个任务。

## 2.2 为什么线程需要独立的调用栈？

假设有两个线程同时调用：
```Java
public int add(int a, int b) {
    int result = a + b;
    return result;
}
```
线程 A 执行 `add(1, 2)`，线程 B 执行 `add(10, 20)`。虽然调用的是同一段代码，但它们的参数和局部变量属于各自的方法调用。线程 A 的 `result` 是 3，线程 B 的 `result` 是 30。这就涉及线程的内存结构。

# 3. 核心区别

| 对比项   | <mark style="background-color: #FF5582A6;">进程</mark> | <mark style="background-color: #FFB8EBA6;">线程</mark> |
| ----- | ---------------------------------------------------- | ---------------------------------------------------- |
| 核心作用  | 资源管理与隔离                                              | 执行代码、参与 CPU 调度                                       |
| 内存    | 通常拥有独立的虚拟地址空间                                        | 共享所属进程的地址空间                                          |
| 数据共享  | 需要进程间通信机制                                            | 可以直接访问共享对象                                           |
| 创建和切换 | 一般开销较大                                               | 一般开销较小                                               |
| 故障影响  | 通常相互隔离                                               | 可能破坏整个进程的共享状态                                        |

多个 Java 线程之间，到底共享什么、不共享什么？感觉还是记不住的东西

|共享|各自独立|
|---|---|
|Java 堆中的对象|Java 虚拟机栈|
|方法区中的类相关数据|程序计数器|
|进程中的文件、网络等资源|本地方法栈|
|静态字段所引用的数据|当前执行位置和寄存器状态|
注意，线程各自拥有调用栈，并不代表线程只能访问自己的数据。它们仍然可以通过共享对象引用访问相同的堆对象。

## 3.1 共享内存会有什么问题？

```Java

    int count = 0;

    void increment() {
        count++;
    }

```

# 4. CPU如何执行多个线程？
假设一个单核单线程的CPU，而 Java 创建了三个线程，CPU并不能真正同时执行三个线程，而是通过调度，当他们轮流运行。

操作系统会保存被切走线程的执行状态，例如程序计数器、寄存器等信息，再恢复另一个线程的状态。这个过程被称为**线程上下文切换**。

如果CPU更现代一点，有多个核心多个线程，那么就可以真正同时执行。

这里要区分两个易混淆概念：
- 并发：多个任务在一段时间内交替执行，不要求在同一时刻执行。
- 并行：多个任务在同一时间(exact the same time)执行

# 5. 一些可能的追问

## 5.1 一个进程可以有多个线程，那一个线程可以属于多个进程吗？

不能。一个线程属于一个进程，不会同时属于多个进程。

## 5.2 一个线程崩溃，会导致整个进程崩溃吗？

不一定。在 Java/Kotlin 中，如果一个线程抛出未捕获的普通异常，那么通常是该线程自身终止。但如果发生 JVM 致命错误或者原生代码访问非法内存等情况，就可能导致整个 JVM 进程退出。

## 5.3 线程越多，处理请求就越快吗？

不是。线程过多会增加内存、上下文切换以及锁竞争开销。对于CPU密集型任务，线程数一般需要结合CPU核心数决定；对于IO密集型任务，因为线程可能经常需要等待外部操作，可以适当使用更多的线程，但也要考虑资源限制

## 5.4 线程和协程的区别

普通 JVM 平台线程由操作系统调度，而 kotlin 协程则由协程运行时负责调度到实际的执行线程上，也就是说，协程最终仍需要线程才能够执行
