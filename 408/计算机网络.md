# 1. 介绍一下TCP和UDP

^0fde80

TCP和UDP都是`传输层协议`

TCP(Transmission Control Protocol)：是一种面向连接、可靠传输的协议。

特点：
- 传输前需要先建立连接
- 能保证数据不丢失、不重复、按顺序到达
- 有确认应答、重传、流量控制、拥塞控制这些机制

常见场景：
- 网页访问
- 文件传输
- 邮件
- 数据库连接

UDP(User Datagram Protocol)：是一种无连接、不保证可靠性的协议

特点(与TCP相反)：
- 无需连接
- 不保证信息一定送达
- 不保证顺序
- 开销小，速度快，实时性更好

常见场景：
- 视频直播
- 语音通话
- 在线游戏
- DNS查询

## 疑问：既然UDP有这些缺点，那以上的场景还在用UDP而不是TCP？

以视频直播为例，如果使用TCP，有一段语音或者信息丢包了，那么就需要重传，表现就是卡了一下，而如果是UDP，那表现就只是轻微杂音，体验可能更好。再说游戏这块，丢了一点包也能继续，而不是完全从丢包的地方重新开始

# 2. 介绍一下HTTP和HTTPS

两者均为应用层协议

HTTP(HyperText Transfer Protocol)：一种应用层协议，用于浏览器和服务器之间传输数据。

它规定的是：
- 请求怎么发
- 响应怎么回
- 请求头、响应头、状态码这些怎么组织

特点：
- 本身是明文传输
- 如果被截获，内容可能看到
- 默认端口是80

HTTPS(HyperText Transfer Protocol Sercure)：本质上还是HTTP，只是加上了TLS(SSL现已弃用)加密

主要提供：
- 加密：即使截获也不能获取内容
- 身份认证：确认访问的是目标服务器，而不是其他的
- 完整性保护：防止数据传输过程中被篡改
- 默认端口是443

## 疑问：加密是怎么加的？

不是从头到尾都是用的一种加密方式，而是非对称加密 + 对称加密 + 数字证书/签名一起配合。

### 1. 为什么不全称都是用非对称加密？

因为全称非对称加密虽然听起来很安全，但是实际上开销很大，会造成不好的用户体验。

### 2. 握手阶段做了什么？

客户端访问服务器，服务器把自己的证书发给客户端，证书里面有服务器的公钥，以及证书颁发机构对它的签名，之后客户端检查证书是否可靠，如果没问题就开始协商一份只有双方知道的会话密钥。

### 3. 后续数据怎么传输？

握手完成后，大部分请求通常都用上面说的那份对称密钥来完成。

原因：
- 速度快
- 适合大量数据传输
- 性能更好
