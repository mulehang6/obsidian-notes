# 1. InnoDB的默认事务等级

MySQL InnoDB 默认的事务隔离级别是 REPEATABLE READ，也就是可重复读。

事务隔离级别一共有四种。

第一种是 READ UNCOMMITTED，读未提交。一个事务可以读取另一个事务还没有提交的数据，所以可能出现脏读、不可重复读和幻读，隔离级别最低。

第二种是 READ COMMITTED，读已提交。只能读取其他事务已经提交的数据，可以解决脏读，但是同一个事务中两次查询可能读到不同的数据，所以仍然可能出现不可重复读和幻读。

第三种是 REPEATABLE READ，可重复读，也是 InnoDB 默认的隔离级别。它保证同一个事务中，多次普通快照读看到的数据基本保持一致，可以解决脏读和不可重复读。InnoDB 通过 MVCC，以及在当前读场景下使用 Next-Key Lock 等机制，也能够避免很多幻读问题。

第四种是 SERIALIZABLE，串行化。隔离级别最高，会让事务之间的并发受到较大限制，可以避免脏读、不可重复读和幻读，但是性能和并发能力也是最差的。

# 2. 解释一下脏读，不可重复读和幻读

- 脏读：读到了其他事务还没有提交的事务，结果其他事务回滚了
- 不可重复读：同一个事务中，执行两次完全相同的查询，结果却不一致（<mark style="background-color: #FF5582A6;">主要关注数据条目本身的变化而非数量</mark>，例如第一次读取时age是18，结果第二次变成了50）
- 幻读：同一个事务中，执行两次完全相同的查询，<mark style="background-color: #FF5582A6;">查询返回的结果条目数变了</mark>，例如第一次查询有3条符合的数据，结果两次查询间有其他事务添加/删除了符合的数据，导致第二次查询时条目数量发生了变化，即从原来的3条变成了2/4条
